## 🛠️ Vibe Security Tools

> Tools for scanning, auditing, and securing AI-generated code.

### Static Analysis & Secret Detection

- [Semgrep](https://semgrep.dev/) — Fast, open-source static analysis that finds bugs and enforces security standards in AI-generated code.
- [Gitleaks](https://github.com/gitleaks/gitleaks) — Detect hardcoded secrets, API keys, and credentials in git repos — a top vibe coding risk.
- [TruffleHog](https://github.com/trufflesecurity/trufflehog) — Searches git history for secrets accidentally committed by AI assistants.
- [Bandit](https://bandit.readthedocs.io/) — Python static analysis tool that finds common security issues in AI-generated Python code.
- [Snyk Code](https://snyk.io/product/snyk-code/) — Developer-first SAST for AI-written code with real-time IDE feedback.
- [Checkov](https://www.checkov.io/) — Static analysis for infrastructure-as-code generated by AI tools.

### Dynamic Analysis & Vulnerability Scanning

- [OWASP ZAP](https://www.zaproxy.org/) — Open-source web application scanner — essential for testing vibe-coded web apps.
- [Nuclei](https://nuclei.projectdiscovery.io/) — Fast vulnerability scanner with a huge community template library.
- [Burp Suite Community](https://portswigger.net/burp/communitydownload) — The pentester's essential proxy and scanner.
- [Nikto](https://cirt.net/Nikto2) — Web server scanner for misconfigurations common in vibe-coded deployments.

### Dependency & Supply Chain

- [Socket.dev](https://socket.dev/) — Protects against malicious npm/PyPI packages pulled in by AI-generated dependency files.
- [OSV-Scanner](https://google.github.io/osv-scanner/) — Google's open-source vulnerability scanner for project dependencies.
- [Dependabot](https://docs.github.com/en/code-security/dependabot) — Automated dependency updates and security alerts on GitHub.
- [OWASP Dependency-Check](https://owasp.org/www-project-dependency-check/) — Identifies known vulnerable components in AI-scaffolded projects.

### AI-Specific Code Security

- [CodeRabbit](https://coderabbit.ai/) — AI-powered code reviewer that flags security issues in every pull request.
- [GitHub Advanced Security](https://docs.github.com/en/get-started/learning-about-github/about-github-advanced-security) — Code scanning, secret scanning, and dependency review built into GitHub.
- [Snyk](https://snyk.io/) — End-to-end developer security platform covering code, containers, and IaC.

## 🐛 Vulnerability Classes in Vibe Code

> Common security vulnerabilities that appear disproportionately in AI-generated code.

| Vulnerability | Description | OWASP Ref |
|---|---|---|
| **Hardcoded Secrets** | API keys, passwords, tokens embedded directly in code by AI | A02 |
| **SQL Injection** | AI-generated queries that concatenate user input unsafely | A03 |
| **XSS (Cross-Site Scripting)** | AI-written front-end code that reflects unescaped input | A03 |
| **Broken Authentication** | Weak session management or missing auth checks in AI-generated routes | A07 |
| **IDOR** | AI-generated CRUD endpoints that skip authorization checks | A01 |
| **Path Traversal** | File handling code that trusts user-supplied paths | A01 |
| **Missing Rate Limiting** | AI-generated APIs with no throttling or abuse controls | A05 |
| **Insecure Deserialization** | AI-written parsers that deserialize untrusted input | A08 |
| **Verbose Error Messages** | AI code that leaks stack traces or internal paths to users | A09 |
| **Insecure Defaults** | AI-scaffolded apps with debug mode, open CORS, or weak TLS | A05 |

## 🏗️ Secure Vibe Coding Checklists

> Run these before deploying any AI-generated code to production.

### Pre-Deploy Vibe Security Checklist

- [ ] Run a secrets scanner (Gitleaks, TruffleHog) on the entire repo history
- [ ] Run SAST (Semgrep, Bandit) — fix all high/critical findings before deploy
- [ ] Audit all third-party dependencies with OSV-Scanner or Snyk
- [ ] Manually review all authentication and authorization logic
- [ ] Test all input fields for injection (SQLi, XSS, Command Injection)
- [ ] Confirm no debug mode, verbose errors, or dev config in production
- [ ] Enforce HTTPS/TLS everywhere — no HTTP fallback
- [ ] Review CORS policy — never use wildcard `*` in production APIs
- [ ] Validate rate limiting on all public-facing API endpoints
- [ ] Review file upload handlers for path traversal and type validation
- [ ] Enable all security headers (CSP, HSTS, X-Frame-Options, etc.)
- [ ] Confirm all secrets are in environment variables / secrets manager, never hardcoded

### AI Prompt Security Checklist

- [ ] Never embed raw user input directly into AI prompts (prompt injection)
- [ ] Sanitize AI model outputs before rendering in UI (output injection)
- [ ] Never pass database credentials or secrets into AI context windows
- [ ] Review AI-suggested code for security anti-patterns before merging
- [ ] Use a code review gate (CodeRabbit, GitHub Advanced Security) on every PR
